# Splunk Security Inspector

Portable contract for Splunk authentication, authorization, transport, audit, and platform-hardening assessments.

## Purpose

Assess Splunk authentication, authorization, encryption, audit, knowledge-object, application, and platform posture through read-only REST and ACS APIs.

## Design guidance

Respect Splunk configuration and namespace precedence, isolate transport settings to the client, and preserve REST versus ACS pagination, permission, deployment, and unavailable-setting states.

## Shared integration contract

This specification requires [shared integration contract version 1.1](./integration-contract.md). The raw contract is available at https://raw.githubusercontent.com/ethanolivertroy/grclanker/main/specs/integration-contract.md.

## Known runtime gaps

- Splunk configuration reads merge default, system, app, and user namespace values using the runtime's documented precedence before any check evaluates.
- REST offset paging and ACS next-link paging record the requested endpoint, item count, server total, and exact cap, malformed-link, repeated-link, or exhaustion stop.
- The per-client verify_ssl switch changes only the Splunk transport and does not mutate process-wide TLS behavior.
- Enterprise Security content coverage and controls without a read status remain manual.

## Authentication

Supported modes:

- Splunk bearer token
- Splunk username/password Basic authentication
- Independent Splunk Cloud ACS token

Credential precedence, highest first:

1. Explicit tool arguments
2. SPLUNK_* environment variables
3. Explicit or default Splunk YAML configuration

Environment variables: `SPLUNK_CONFIG_FILE`, `SPLUNK_URL`, `SPLUNK_TOKEN`, `SPLUNK_USERNAME`, `SPLUNK_PASSWORD`, `SPLUNK_STACK`, `SPLUNK_ACS_TOKEN`, `SPLUNK_ACS_BASE_URL`, `SPLUNK_VERIFY_SSL`, `SPLUNK_TIMEOUT`

Configuration locations: ~/.splunk-sec-inspector/config.yaml, Explicit path from config_file or SPLUNK_CONFIG_FILE

Credential and deployment variants: Splunk Enterprise management API, Splunk Cloud management API, Splunk Cloud ACS

Configuration fields: `url`, `token`, `username`, `password`, `stack`, `acs_token`, `acs_base_url`, `verify_ssl`, `timeout_seconds`

Malformed configuration: Reject malformed or ambiguous configuration before any request; never echo credential values.

## Integration-specific scrubbing

Shared contract version: 1.1.

Projection stage: Project records to verdict-consumed fields, scrub configured and discovered credentials, then scrub again at every report and archive write sink.

Sensitive fields and values: token, password, authorization, cookie, session, hec_token, email, url

Credential formats: Splunk bearer tokens, ACS tokens, Basic credentials, session cookies, HEC tokens

Reviewed benign exceptions: Stable non-secret resource identifiers and public documentation URLs remain visible unless carried in a credential field.

Integration-specific rules:

- Withhold undocumented error bodies; retain only status, media type, byte length, and allowlisted vendor error codes.
- Remove URL user information, queries, and fragments from evidence and reject off-origin pagination links.
- Unavailable counts, arrays, maps, and negative flags are null rather than fabricated empty values.
