# Elastic Security Inspector

Portable contract for Elasticsearch identity, authorization, TLS, lifecycle, snapshot, Watcher, ingest, Kibana, and Fleet assessments.

## Purpose

Assess Elasticsearch and Kibana identity, authorization, transport, lifecycle, snapshot, alerting, ingest, and Fleet posture through read-only APIs.

## Design guidance

Resolve layered settings before evaluating them, preserve Elasticsearch and Kibana target boundaries, and keep missing products, privileges, fields, pages, and child reads distinct from complete empty inventories.

## Shared integration contract

This specification requires [shared integration contract version 1.1](./integration-contract.md). The raw contract is available at https://raw.githubusercontent.com/ethanolivertroy/grclanker/main/specs/integration-contract.md.

## Known runtime gaps

- The collector resolves persistent settings before transient settings and transient settings before defaults, then projects only fields used by the 23 checks.
- Every paged users, roles, API-key, policy, watch, pipeline, space, and Fleet read carries seen, total, page count, truncation, and the exact terminal condition.
- Kibana reads are explicitly not configured when no Kibana origin exists; dependent checks remain manual and unrelated Elasticsearch checks retain their evidence-based verdicts.
- Client certificates, custom certificate authorities, and transport skip-verify are not accepted authentication modes.

## Authentication

Supported modes:

- Elasticsearch API key
- HTTP Basic username/password
- Bearer token
- Elastic Cloud API key for deployment metadata

Credential precedence, highest first:

1. Explicit tool arguments
2. ELASTIC_* and KIBANA_* environment variables
3. Explicit or default Elastic YAML configuration

Environment variables: `ELASTIC_SEC_INSPECTOR_CONFIG`, `ELASTICSEARCH_URL`, `ELASTIC_URL`, `KIBANA_URL`, `KIBANA_SPACE_ID`, `ELASTIC_API_KEY`, `ELASTIC_USERNAME`, `ELASTIC_PASSWORD`, `ELASTIC_BEARER_TOKEN`, `ELASTIC_CLOUD_API_KEY`, `ELASTIC_CLOUD_API_URL`, `ELASTIC_TIMEOUT`

Configuration locations: ~/.elastic-sec-inspector/config.yaml, Explicit path from config_file or ELASTIC_SEC_INSPECTOR_CONFIG

Credential and deployment variants: Self-managed Elasticsearch and Kibana, Elastic Cloud deployment metadata, Optional Kibana space

Configuration fields: `elasticsearch_url`, `kibana_url`, `kibana_space_id`, `api_key`, `username`, `password`, `bearer_token`, `cloud_api_key`, `cloud_api_url`, `timeout_seconds`, `max_retries`

Malformed configuration: Reject malformed or ambiguous configuration before any request; never echo credential values.

## Integration-specific scrubbing

Shared contract version: 1.1.

Projection stage: Project records to verdict-consumed fields, scrub configured and discovered credentials, then scrub again at every report and archive write sink.

Sensitive fields and values: api_key, password, authorization, bearer_token, cloud_api_key, email, metadata, url

Credential formats: Elasticsearch ApiKey headers, Basic credentials, bearer tokens, Elastic Cloud API keys

Reviewed benign exceptions: Stable non-secret resource identifiers and public documentation URLs remain visible unless carried in a credential field.

Integration-specific rules:

- Withhold undocumented error bodies; retain only status, media type, byte length, and allowlisted vendor error codes.
- Remove URL user information, queries, and fragments from evidence and reject off-origin pagination links.
- Unavailable counts, arrays, maps, and negative flags are null rather than fabricated empty values.
