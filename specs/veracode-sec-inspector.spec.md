# Veracode Security Inspector

Portable contract for Veracode scan coverage, policy, findings, SCA, DAST, and access-control assessments.

## Purpose

Assess Veracode application scan coverage, policy compliance, finding hygiene, SCA, DAST, and identity posture through HMAC-signed REST APIs.

## Design guidance

Sign the exact same-origin request after final query construction. Exhaust HAL totals before deriving portfolio metrics, and retain every failed or skipped per-application, workspace, credential, sandbox, project, and dynamic-analysis read as unavailable evidence.

## Shared integration contract

This specification requires [shared integration contract version 1.1](./integration-contract.md). The raw contract is available at https://raw.githubusercontent.com/ethanolivertroy/grclanker/main/specs/integration-contract.md.

## Known runtime gaps

- Every HAL list proves page exhaustion from page.number, page.total_pages, and page.total_elements; caller application, workspace, and analysis sampling caps mark dependent checks incomplete.
- Per-application findings, reports, sandboxes, SCA projects, and dynamic scan configuration failures remain named not-collected markers and never become empty lists.
- Every request is signed over the exact method, host, path, and query using VERACODE-HMAC-SHA-256 after same-origin URL resolution.
- Legacy XML APIs are intentionally not called; controls without decisive REST fields remain manual rather than inferred from the legacy design.

## Authentication

Supported modes:

- VERACODE-HMAC-SHA-256 API ID and secret signing

Credential precedence, highest first:

1. Explicit tool arguments
2. VERACODE_* environment variables
3. Selected profile in the Veracode credentials INI file

Environment variables: `VERACODE_API_PROFILE`, `VERACODE_API_CREDENTIALS_FILE`, `VERACODE_API_KEY_ID`, `VERACODE_API_KEY_SECRET`, `VERACODE_REGION`, `VERACODE_API_BASE_URL`, `VERACODE_TIMEOUT`

Configuration locations: ~/.veracode/credentials, Explicit path from credentials_file or VERACODE_API_CREDENTIALS_FILE

Credential and deployment variants: us: api.veracode.com, eu: api.veracode.eu, us-fed: api.veracode.us, Explicit same-origin API base URL

Configuration fields: `veracode_api_key_id`, `veracode_api_key_secret`

Malformed configuration: Reject malformed or ambiguous configuration before any request; never echo credential values.

## Integration-specific scrubbing

Shared contract version: 1.1.

Projection stage: Project records to verdict-consumed fields, scrub configured and discovered credentials, then scrub again at every report and archive write sink.

Sensitive fields and values: veracode_api_key_secret, api_id, authorization, nonce, signature, user_name, email, application_name

Credential formats: Veracode API key IDs, 128-character HMAC secret keys, VERACODE-HMAC-SHA-256 Authorization headers

Reviewed benign exceptions: Stable non-secret resource identifiers and public documentation URLs remain visible unless carried in a credential field.

Integration-specific rules:

- Withhold undocumented error bodies; retain only status, media type, byte length, and allowlisted vendor error codes.
- Remove URL user information, queries, and fragments from evidence and reject off-origin pagination links.
- Unavailable counts, arrays, maps, and negative flags are null rather than fabricated empty values.
