# New Relic Security Inspector

Portable contract for New Relic identity, API access, alerting, and telemetry-governance assessments.

## Purpose

Assess New Relic identity, API access, alerting, telemetry retention, obfuscation, dashboard, synthetics, and infrastructure posture.

## Design guidance

Use schema-cited NerdGraph selections, preserve every account and cursor boundary, and keep fallback queries, unavailable fields, denied accounts, partial connections, and complete empty results semantically distinct.

## Shared integration contract

This specification requires [shared integration contract version 1.1](./integration-contract.md). The raw contract is available at https://raw.githubusercontent.com/ethanolivertroy/grclanker/main/specs/integration-contract.md.

## Known runtime gaps

- NerdGraph queries request explicit schema-cited fields and apply a documented fallback only when the primary field or query is unavailable.
- Every account-scoped collection records success, denial, schema error, cursor anomaly, seen count, and total count independently before cross-account aggregation.
- A cursor is complete only when hasNextPage is false and any totalCount is reconciled; a missing or repeated endCursor and every cap exit are truncated.
- Controls whose decisive New Relic field is unavailable in the caller's schema or subscription remain manual.

## Authentication

Supported modes:

- New Relic user API key

Credential precedence, highest first:

1. Explicit tool arguments
2. NEW_RELIC_* environment variables
3. Explicit or default New Relic YAML configuration

Environment variables: `NEW_RELIC_SEC_INSPECTOR_CONFIG`, `NEW_RELIC_API_KEY`, `NEW_RELIC_ACCOUNT_ID`, `NEW_RELIC_REGION`, `NEW_RELIC_TIMEOUT`, `NEW_RELIC_AUDIT_WINDOW_DAYS`

Configuration locations: ~/.newrelic-sec-inspector/config.yaml, Explicit path from config_file or NEW_RELIC_SEC_INSPECTOR_CONFIG

Credential and deployment variants: US NerdGraph and REST origins, EU NerdGraph and REST origins, One or more account IDs

Configuration fields: `api_key`, `account_ids`, `region`, `timeout_seconds`, `audit_window_days`

Malformed configuration: Reject malformed or ambiguous configuration before any request; never echo credential values.

Credential formats: NRAK user API keys, bearer headers, synthetics secure credentials, private-key and cloud-key patterns

Reviewed benign exceptions: Stable non-secret resource identifiers and public documentation URLs remain visible unless carried in a credential field.

Integration-specific rules:

- Withhold undocumented error bodies; retain only status, media type, byte length, and allowlisted vendor error codes.
- Remove URL user information, queries, and fragments from evidence and reject off-origin pagination links.
- Unavailable counts, arrays, maps, and negative flags are null rather than fabricated empty values.
