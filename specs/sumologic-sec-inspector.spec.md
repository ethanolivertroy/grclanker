# Sumo Logic Security Inspector

Portable contract for Sumo Logic identity, key, collector, ingest, retention, monitor, and content-sharing assessments.

## Purpose

Assess Sumo Logic identity, keys, collectors, ingest budgets, audit, retention, monitors, and content-sharing posture through read-only APIs.

## Design guidance

Never treat personal-scope fallback as organization-wide proof. Preserve cursor, offset, folder-child, capability, plan, and approved-domain review inputs through complete-population evaluation.

## Shared integration contract

This specification requires [shared integration contract version 1.1](./integration-contract.md). The raw contract is available at https://raw.githubusercontent.com/ethanolivertroy/grclanker/main/specs/integration-contract.md.

## Known runtime gaps

- Organization-scoped and personal-scoped responses are never interchangeable; every collection records its exact scope and a personal fallback cannot prove an organization-wide pass.
- Cursor and offset walkers mark every cap, repeated cursor, missing total, rejected continuation, and failed child permission read as incomplete.
- The content permission sweep keeps folder witnesses and exact failed child IDs so aggregate completeness reflects mixed success, all-failed, and zero-attempt cases separately.
- Three controls remain manual because the public API exposes no decisive read endpoint.

## Authentication

Supported modes:

- Sumo Logic access ID and access key using HTTP Basic authentication

Credential precedence, highest first:

1. Explicit tool arguments
2. SUMOLOGIC_* environment variables
3. Explicit or default Sumo Logic YAML configuration

Environment variables: `SUMOLOGIC_CONFIG_FILE`, `SUMOLOGIC_ACCESS_ID`, `SUMOLOGIC_ACCESS_KEY`, `SUMOLOGIC_DEPLOYMENT`, `SUMOLOGIC_ENDPOINT`, `SUMOLOGIC_TIMEOUT`

Configuration locations: ~/.sumologic-sec-inspector/config.yaml, Explicit path from config_file or SUMOLOGIC_CONFIG_FILE

Credential and deployment variants: au, ca, ch, de, esc, eu, fed, in, jp, kr, us1, us2, Explicit regional endpoint

Configuration fields: `access_id`, `access_key`, `deployment`, `endpoint`, `timeout_seconds`

Malformed configuration: Reject malformed or ambiguous configuration before any request; never echo credential values.

## Integration-specific scrubbing

Shared contract version: 1.1.

Projection stage: Project records to verdict-consumed fields, scrub configured and discovered credentials, then scrub again at every report and archive write sink.

Sensitive fields and values: accessId, accessKey, authorization, email, url, token, headers

Credential formats: Sumo Logic access IDs, Sumo Logic access keys, Basic authorization headers, webhook URLs

Reviewed benign exceptions: Stable non-secret resource identifiers and public documentation URLs remain visible unless carried in a credential field.

Integration-specific rules:

- Withhold undocumented error bodies; retain only status, media type, byte length, and allowlisted vendor error codes.
- Remove URL user information, queries, and fragments from evidence and reject off-origin pagination links.
- Unavailable counts, arrays, maps, and negative flags are null rather than fabricated empty values.
