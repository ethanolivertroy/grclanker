# LaunchDarkly Security Inspector

Portable contract for LaunchDarkly member, role, token, environment, flag, audit, integration, and webhook assessments.

## Purpose

Assess LaunchDarkly member, role, token, environment, flag, audit, integration, webhook, and Relay Proxy configuration posture.

## Design guidance

Evaluate full role statements and approval objects rather than names, preserve project and environment scope, and retain exact pagination, beta-field, limit, and unavailable-read semantics.

## Shared integration contract

This specification requires [shared integration contract version 1.1](./integration-contract.md). The raw contract is available at https://raw.githubusercontent.com/ethanolivertroy/grclanker/main/specs/integration-contract.md.

## Known runtime gaps

- Custom-role evaluation uses every policy statement, resource selector, action, effect, and not-action field; a role name is never treated as proof of privilege.
- Project, environment, token, flag, status, audit, integration, and webhook listings each preserve their own cap, total, next offset, and exact completeness state.
- SDK-key posture uses environment creation and key-rotation metadata only where the API returns it; static Relay Proxy deployment visibility remains manual.
- Account SSO enforcement, static Relay Proxy deployment posture, and complete integration enumeration remain manual where no public read exists.

Configuration locations: ~/.launchdarkly-sec-inspector/config.yaml, Explicit path from config_file or LAUNCHDARKLY_CONFIG

Credential and deployment variants: LaunchDarkly SaaS, Federal instance, Explicit same-origin REST API base URL

Configuration fields: `api_token`, `base_url`, `api_version`, `timeout_seconds`, `project_keys`, `allowed_domains`

Malformed configuration: Reject malformed or ambiguous configuration before any request; never echo credential values.

## Integration-specific scrubbing

Shared contract version: 1.1.

Projection stage: Project records to verdict-consumed fields, scrub configured and discovered credentials, then scrub again at every report and archive write sink.

Sensitive fields and values: api_token, accessToken, sdkKey, mobileKey, clientSideId, secret, url, email, authorization

Credential formats: LaunchDarkly API access tokens, SDK keys, mobile keys, client-side IDs, webhook secrets

Reviewed benign exceptions: Stable non-secret resource identifiers and public documentation URLs remain visible unless carried in a credential field.

Integration-specific rules:

- Withhold undocumented error bodies; retain only status, media type, byte length, and allowlisted vendor error codes.
- Remove URL user information, queries, and fragments from evidence and reject off-origin pagination links.
- Unavailable counts, arrays, maps, and negative flags are null rather than fabricated empty values.
