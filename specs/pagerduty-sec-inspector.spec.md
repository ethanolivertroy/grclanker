# PagerDuty Security Inspector

Portable contract for PagerDuty access, escalation, on-call, audit, webhook, dependency, and change-event assessments.

## Purpose

Assess PagerDuty access, escalation, on-call, audit, webhook, integration, dependency, and change-event posture through read-only APIs.

## Design guidance

Keep classic and cursor pagination separate, preserve credential scope and plan gates, and treat missing dates, child failures, and the 10,000-record ceiling as explicit uncertainty rather than compliance.

## Shared integration contract

This specification requires [shared integration contract version 1.1](./integration-contract.md). The raw contract is available at https://raw.githubusercontent.com/ethanolivertroy/grclanker/main/specs/integration-contract.md.

## Known runtime gaps

- Classic offset endpoints and cursor endpoints use separate walkers; the documented 10,000-record offset ceiling is a truncation boundary, not exhaustion.
- Credential scope, account subdomain, service region, From header, plan-gated abilities, and per-resource child failures are retained as distinct collection facts.
- Webhook URLs are projected to safe origin data, secret headers and integration keys are withheld, and every missing date remains unknown rather than fresh.
- SSO enforcement, API-key inventory, and analytics-role visibility remain plan- or permission-gated manual evidence.

Supported modes:

- PagerDuty API token

Configuration locations: ~/.config/grclanker/pagerduty.json, Explicit path from config_file or PAGERDUTY_CONFIG_FILE

Credential and deployment variants: US service region, EU service region, Scoped credential requiring account subdomain and From header

Configuration fields: `api_token`, `access_token`, `client_id`, `client_secret`, `subdomain`, `from_email`, `region`, `base_url`, `timeout_seconds`

Malformed configuration: Reject malformed or ambiguous configuration before any request; never echo credential values.

Credential refresh: POST the PagerDuty identity token endpoint with the client_credentials grant for scoped OAuth credentials.

## Integration-specific scrubbing

Shared contract version: 1.1.

Projection stage: Project records to verdict-consumed fields, scrub configured and discovered credentials, then scrub again at every report and archive write sink.

Sensitive fields and values: api_token, access_token, client_secret, authorization, integration_key, routing_key, headers, email, url

Credential formats: PagerDuty REST API tokens, OAuth access tokens, OAuth client secrets, integration and routing keys, webhook custom headers

Reviewed benign exceptions: Stable non-secret resource identifiers and public documentation URLs remain visible unless carried in a credential field.

Integration-specific rules:

- Withhold undocumented error bodies; retain only status, media type, byte length, and allowlisted vendor error codes.
- Remove URL user information, queries, and fragments from evidence and reject off-origin pagination links.
- Unavailable counts, arrays, maps, and negative flags are null rather than fabricated empty values.
